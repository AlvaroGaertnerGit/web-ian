# CLAUDE.md

## PROJECT: Private Detective Website

This repository contains a professional website for a private detective / private investigation firm.

The goal is NOT to create a generic "detective website".

The goal is to create a premium digital experience that communicates:

- Trust
- Professionalism
- Discretion
- Intelligence
- Precision
- Elegance
- Legitimacy
- Confidentiality

while making the actual information about private investigation services extremely easy to understand and access.

The visual experience must enhance the content, never compete with it.

---

# 1. CORE PRODUCT PRINCIPLE

The website exists to help a potential client answer three questions as quickly as possible:

1. Can this detective help with my situation?
2. Can I trust them?
3. What should I do next?

Every design and technical decision must support these three questions.

The website should communicate:

> "You have a question. We investigate the facts and help you obtain evidence."

Do NOT position the business as a movie-style detective agency.

Avoid clichés such as:

- Magnifying glasses
- Detective hats
- Noir caricatures
- Excessive silhouettes
- Fake surveillance imagery
- Generic spy imagery
- "Secret agent" aesthetics
- Cyberpunk aesthetics
- Hacker aesthetics

The brand should feel like a serious professional investigation firm.

---
# 1.1. LANGUAGE — SPANISH ONLY

The website's public-facing language is Spanish.

ALL user-facing content must be written in Spanish, including:

- Navigation
- Headings
- Subheadings
- Buttons
- CTAs
- Forms
- Form validation messages
- Error messages
- Success messages
- Service descriptions
- FAQ
- Blog content
- Metadata
- SEO titles
- SEO descriptions
- Open Graph metadata
- Accessibility labels
- Image alt text
- Structured data textual fields
- Footer
- Cookie/privacy interface
- Any other visible or user-facing text

Do NOT use English UI copy.

Technical code may use English for:

- Variable names
- Function names
- Component names
- File names
- Types
- Interfaces
- Internal comments
- Git commit messages

However, anything visible to the final user must be in Spanish.

Use natural, professional Spanish appropriate for Spain.

Avoid literal translations from English.

The tone should be:

- Professional
- Calm
- Discreet
- Clear
- Trustworthy
- Human
- Elegant

Avoid exaggerated marketing language.

Use correct Spanish typography and punctuation.

When referring to legal, professional or investigative terminology, use terminology appropriate to the Spanish private investigation sector and Spanish legislation.

Never fabricate legal terminology, credentials or regulatory claims.

# 3. VISUAL PHILOSOPHY

We are open to advanced visual techniques such as:

- Parallax
- Layered depth
- Glassmorphism
- Soft transparency
- Blur
- Grain/noise textures
- Cinematic imagery
- Scroll-driven transitions
- Masked imagery
- Subtle gradients
- Perspective
- Depth-based motion
- Magnetic interactions
- Microinteractions
- Reveal animations
- Sticky storytelling sections

BUT:

Effects are subordinate to content.

Never add an effect simply because it looks impressive.

For every major visual effect ask:

> Does this improve understanding, hierarchy, emotion or brand perception?

If not, remove it.

---

# 4. GLASSMORPHISM RULE

Glassmorphism is NOT a mandatory design language.

It may be used selectively when it makes sense.

Use it for things such as:

- Floating navigation
- Small information cards
- Contact panels
- Trust badges
- Supporting UI
- Layered content
- Interactive elements

Do NOT turn the entire website into translucent glass cards.

Avoid:

- Excessive blur
- Low contrast text
- Floating everything
- Excessive borders
- "Glassmorphism everywhere"

The final design must feel sophisticated rather than trendy.

---

# 5. INFORMATION HIERARCHY

The content is more important than visual effects.

The hierarchy should generally prioritize:

1. What the detective does
2. Who they help
3. Services
4. Trust / credentials
5. How the investigation works
6. Evidence / results
7. Frequently asked questions
8. Contact / consultation

The visitor should NEVER have to fight the interface to find basic information.

# 8. LEGAL AND ETHICAL POSITIONING

This is a private investigation website operating in Spain.

Legal accuracy is critical.

Never make claims such as:

- "We can investigate anyone."
- "We can access any phone."
- "We can hack accounts."
- "We can obtain private messages."
- "We can track anyone."
- "We guarantee evidence."
- "We guarantee a result."

Never imply illegal surveillance.

Do not suggest bypassing:

- Privacy laws
- Data protection laws
- Communications secrecy
- Judicial requirements
- Consent requirements
- Legitimate-interest requirements

The website should communicate lawful, proportionate and professional investigation.

Where appropriate, emphasize:

- Licensed professionals
- Confidentiality
- Lawful evidence gathering
- Professional reports
- Legitimate interest
- Proportionality
- Professional methodology

Do not invent credentials.

Do not invent TIP, RNSP, years of experience, number of cases, memberships, certifications or awards.

Use placeholders until the real information is provided.

# 12. ANIMATION PRINCIPLES

Animations should feel:

- Smooth
- Expensive
- Controlled
- Intentional

Preferred:

- 200–800ms transitions depending on interaction
- Subtle easing
- Scroll-triggered reveals
- Layered parallax
- Image movement
- Text reveals
- Soft opacity transitions
- Small scale changes

Avoid:

- Constant motion
- Excessive bouncing
- Distracting looping animations
- Huge text transformations
- Long loading animations
- Animation that blocks reading
- Animation that harms accessibility

Respect:

`prefers-reduced-motion`

---

# 13. PARALLAX

Parallax can be used as a storytelling device.

Good use cases:

- Hero imagery
- Investigation/documentary imagery
- Section transitions
- Large background compositions
- Layered editorial sections

Do not use parallax on every section.

The website should still feel premium when all animation is disabled.

---

# 14. RESPONSIVE DESIGN

The website must be designed mobile-first.

Never simply shrink the desktop layout.

Mobile priorities:

1. Readability
2. CTA accessibility
3. Navigation
4. Service discovery
5. Contact
6. Performance

Avoid horizontal overflow.

Test:

- Small mobile
- Large mobile
- Tablet
- Laptop
- Large desktop
- Ultra-wide screens

---

# 15. ACCESSIBILITY

Accessibility is mandatory.

Follow WCAG principles.

Ensure:

- Sufficient contrast
- Keyboard navigation
- Visible focus states
- Semantic HTML
- Accessible buttons
- Accessible forms
- Meaningful alt text
- Proper heading hierarchy
- Reduced motion support
- No information communicated only through animation
- No tiny text

Do not sacrifice accessibility for visual effects.

---

# 16. PERFORMANCE

The website should feel fast.

Prioritize:

- Next.js optimizations
- Image optimization
- Lazy loading
- Appropriate image formats
- Minimal client-side JavaScript
- Server Components where possible
- Code splitting
- Avoiding unnecessary dependencies
- Avoiding huge animation libraries when CSS/native APIs are enough

Do not introduce a dependency simply because it makes one animation easier.

---

# 22. COMPONENT ARCHITECTURE

Build reusable components.

Avoid creating giant page components.

Prefer:

components/
├── layout/
├── navigation/
├── sections/
├── services/
├── forms/
├── cards/
├── typography/
├── media/
└── ui/

Use composition instead of duplication.

Keep components focused.

---

# 23. SERVER VS CLIENT COMPONENTS

Prefer Server Components by default.

Use Client Components only when required for:

- Interactivity
- Browser APIs
- Animations requiring client state
- Forms with client-side state
- Interactive navigation
- Motion logic

Do not turn entire pages into Client Components unnecessarily.

---

# 24. CODE QUALITY

Use:

- TypeScript
- Strict typing
- Clear naming
- Small focused functions
- Reusable components
- Semantic HTML
- Predictable state management

Avoid:

- `any` unless absolutely justified
- Duplicate logic
- Magic numbers
- Giant components
- Unnecessary abstractions
- Dead code
- Commenting obvious code

> "It feels intentionally designed."

- Spacing
- Typography
- Hierarchy
- Alignment
- Contrast
- Animation
- Responsive behavior
- Empty states
- Hover states
- Focus states

- Error states

# 26. NO PREMATURE DESIGN COMMITMENT

Do not immediately implement the first visual idea.

Before building the final interface:

1. Understand the actual business.
2. Understand its services.
3. Understand its clients.
4. Understand its geographic market.
5. Research competitors.
6. Define positioning.
7. Establish the visual direction.
8. Define the information architecture.
9. Then implement.

The visual design must emerge from the business strategy.

# 29. TRUST

Trust is more important than visual spectacle.

The website must communicate:

> "This is a serious professional."

not:

> "This is a cool website."

If an animation conflicts with trust, remove the animation.

If glassmorphism reduces readability, remove the glass.

If a visual effect makes the company look like a tech startup instead of a professional investigation firm, remove it.

---

# 30. DEVELOPMENT WORKFLOW

When working on a new feature:

1. Inspect existing implementation.
2. Understand dependencies.
3. Check relevant `.claude` instructions.
4. Plan the change.
5. Implement the smallest coherent solution.
6. Test.
7. Check responsive behavior.
8. Check accessibility.
9. Check visual consistency.
10. Check performance.
11. Remove unnecessary code.

Do not rewrite unrelated parts of the application.

---

# 31. BEFORE EVERY MAJOR UI CHANGE

Ask:

- What user problem does this solve?
- Does it improve hierarchy?
- Does it improve trust?
- Does it improve conversion?
- Does it improve comprehension?
- Does it preserve accessibility?
- Does it preserve performance?

If the answer is mostly "no", reconsider the change.
